# 53 — Verify-path retry_scan regression (best==NULL) + enroll loop bound

**What to fix:**
In `libfprint/drivers/goodixtls/goodix5e0a.c:on_read_img (~950-960)`:
- Non-enroll path calls `fpi_image_device_retry_scan` when `claim_best_frame` returns NULL. History forbids `retry_scan` in verify — must `image_captured` unconditionally or the PAM claim deadlocks (`already claimed`, ticket 19).
- Enroll path `retry_scan + next_state` on `img==NULL` / low minutiae has no counter; `FDT_UP` 30s re-issue loop holds claim with no progress (apparent hang).

**Settled facts (19/20/47/49):**
- Verify must `image_captured + mark_completed + report_finger(FALSE)` immediately; lift-polling enroll-only.
- 2s `retry_guard` + `FDT_UP 0x34` parking until genuine release; `CANCELLED` never re-issues (`scan_ssm==ssm` check); timeout/error != release, re-issue `0x34`. 30s stop-loss (clients ~25s).
- `bz3_threshold=14`, `ENROLL_MIN 12/15`, stages 5 — never lower to fix quality (ticket 43).

**Status:** closed (rule-7 pair passed on final driver 2026-09-11)

**Rescoped Directives (2026-09-11 Audit):**
1. **Verify NULL-best Path:**
   - When `self->best_img == NULL` (all frames in touch rejected as poor/blank) in verify mode:
     - Do NOT call `fpi_image_device_retry_scan` (causes PAM `already claimed` deadlocks, Ticket 19).
     - Do NOT call `fpi_ssm_mark_failed` (triggers `fpi_image_device_session_error`, marks session dirty, sets `warm_ok = FALSE`, destroying parked TLS and forcing cold bring-up).
     - Instead, synthesize an empty/blank `FpImage` ($64 \times 80$, initialized to 0) and deliver it via `fpi_image_device_image_captured(FP_IMAGE_DEVICE(dev), img)`.
     - Core minutiae detection finds 0 minutiae, Bozorth3 scores 0 (< 14), and libfprint reports clean `verify-no-match` to PAM.
     - The scan SSM marks completed cleanly with `error = NULL`, preserving `warm_ok = TRUE` and the 30-second parked TLS session.
2. **Enrollment Path:**
   - Do NOT impose a hard driver-level retry counter (e.g. 5 attempts). Small $64 \times 80$ sensor requires user repositioning; hard aborts frustrate enrollment. Client-side D-Bus timeouts (25–30s) already bound inactive enrollment sessions.

**Acceptance:**
- Verify mode never calls `retry_scan`.
- An unprimed or blank tap in verify results in clean `verify-no-match` without error, and subsequent `sudo` unlocks reuse the parked TLS session (<100ms).
- Driver compiles cleanly with `ninja`.
